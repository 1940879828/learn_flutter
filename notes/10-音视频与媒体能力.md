- 能写出一个最小媒体页面：选择图片、预览图片、播放视频、管理播放生命周期。
- 为接手 `flutter-spell-ai` 的图片转视频、视频模板、相册保存和媒体预览做准备。

## Web 前端迁移映射

- Web `<img>` 对应 Flutter `Image`、`CachedNetworkImage`、自定义 provider。
- Web `<video>` 对应 Flutter `video_player` 和平台播放器封装。
- Web Audio API 在 Flutter 中通常依赖插件生态，常见选择包括 `just_audio`、`audioplayers`、录音插件等。
- 浏览器 Blob/Object URL 思路可迁移到 Dart `File`、缓存路径、远程 URL、本地 asset。
- Web autoplay、muted、visibility 策略，在移动端变成播放器生命周期、页面可见性、App lifecycle、权限和平台限制。

目标项目当前公开依赖中没有明显的通用音频播放/录音插件，因此学习时先按“能力预研”处理：

- 只播放短音效：关注延迟、预加载、音量、并发播放。
- 播放长音频：关注后台播放、锁屏控制、音频焦点、进度同步。
- 录音：关注麦克风权限、编码格式、文件路径、上传、隐私提示。
- 音视频混合：关注视频静音、背景音乐、导出、平台编解码能力。

后续如果目标项目明确要做音频功能，需要先做技术选型文档，再改生产项目。

## QA 问答

### Q1：`asset`、`network`、`file` 视频源有什么本质差异？
`asset` 是包内静态资源，`network` 依赖网络和缓存策略，`file` 依赖本地文件生命周期。面试时会问预加载、可恢复播放和异常恢复策略。

### Q2：`VideoPlayerController` 为什么要 `dispose`？
播放器资源包含底层通道和解码器，未释放会导致内存、文件句柄、平台通道泄漏，尤其页面频繁切换时更明显。

### Q3：什么时候用 `photo_manager`，什么时候用 `image_picker`？
`image_picker` 更偏快速选取单张/多张；`photo_manager` 更适合相册列表、读取管理、保存与高级控制。目标项目的相册交互通常是两者组合。

### Q4：媒体失败后应当怎么设计用户反馈？
不能只 show 一个通用错误 toast，要区分权限、网络、格式、码率、初始化失败，并给出可执行操作（去设置、重试、选择本地文件）。

### Q5：音频能力为什么不在这个项目里直接加？
因为音视频属于平台敏感模块：后台行为、音频焦点、麦克风权限、编码格式、资源消耗都牵涉链路，必须先做技术选型和平台验证。
