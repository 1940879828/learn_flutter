# 26 AI 生成任务链路方法论

## 这份手册解决什么问题

AI 生成类功能不是一个提交按钮。它包含 prompt 输入、模板/参数、额度校验、任务创建、上传、轮询、等待状态、失败重试、结果预览、保存分享和付费提示。

这份手册用于设计图片/视频/文本生成任务的端到端链路。

## 什么时候使用

- 适合：AI 图片生成、图生视频、文生视频、prompt 编辑、生成结果页、任务历史。
- 不适合：普通静态表单或不需要异步任务状态的本地功能。

## 一句话原则

AI 生成的核心体验是让用户低成本得到第一次可用结果，而不是展示一堆模型参数。

## 决策表

| 环节 | 设计重点 | 原因 |
| --- | --- | --- |
| prompt 输入 | 示例、模板、草稿 | 降低空白压力 |
| 参数选择 | 默认值 + 高级折叠 | 不让新手被参数淹没 |
| 提交前 | 额度、权限、素材校验 | 避免失败后才解释 |
| 创建任务 | 幂等、loading、防重复点 | 生成成本高 |
| 等待中 | 进度、可离开、可恢复 | 等待本身要被设计 |
| 轮询 | 超时、取消、退避 | 控制资源和体验 |
| 失败 | 可重试、可改 prompt | 失败不是终点 |
| 结果页 | 保存、分享、再生成、编辑 | 把结果变成下一步 |
| 付费/额度 | 先解释价值再拦截 | 减少突兀感 |

## 固定检查问题

```text
用户第一次成功动作是什么？
生成前必须校验哪些素材、权限、额度和参数？
任务状态有哪些：排队、生成中、成功、失败、取消、超时？
用户离开页面后任务是否继续？回来如何恢复？
结果生成后下一步是什么？
```

## Flutter 实现拆分

```text
Create page
  负责输入、模板、参数、提交入口。

Params model
  负责把 UI 选择转成接口 body 所需结构。

Generation repository
  负责创建任务、查询进度、取消或重试。

Task provider / VM
  管理 idle、submitting、polling、success、error。

Result page
  展示结果、保存、分享、再生成。
```

## 常见坏味道

- prompt 输入框空白，没有示例和模板。
- UI 直接拼复杂生成 body。
- 提交按钮可重复点击，创建多个任务。
- 轮询没有超时和取消。
- 生成等待只显示无信息 loading。
- 结果页没有下一步，只能返回。
- 用户还没体验价值就弹订阅或额度解释。

## 验收标准

- 首次用户能在低成本路径里完成一次生成。
- 所有任务状态都有可见反馈。
- 页面离开/回来不会丢任务状态。
- 失败后能重试或修改输入。
- 结果页提供保存、分享、编辑或再生成。
