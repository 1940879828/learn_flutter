# 07 路由、导航与页面组织 - 教学正文

这一章要解决的是：你能不能自己组织一个多页面 Flutter App，而不是只在按钮里临时 push 一个页面。

## 先看结论

路由先分成五件事：

1. 路由表：哪些 URL-like path 对应哪些页面。
2. 跳转方式：`push`、`go`、`pop` 分别如何影响返回栈。
3. 参数传递：path、query、extra 分别放什么。
4. 返回值：下一页怎么把结果交回上一页。
5. redirect：进入页面前如何按状态改写目标路由。

## 第 1 步：从 `MaterialApp` 升级到 `MaterialApp.router`

普通小 demo 常写：

```dart
MaterialApp(home: LearningHomePage())
```

到了多页面应用，需要让 App 使用统一路由表：

```dart
MaterialApp.router(routerConfig: router)
```

这一步类似从“组件里手动切页面”升级到“应用有统一路由表”。

## 第 2 步：集中管理 path

本章把 path 放在 `LearningRoutes`：

- `/`：学习目录。
- `/chapter-07/routes`：07 路由实验室。
- `/chapter-07/tasks/:taskId`：任务详情。
- `/chapter-07/create`：创建任务。
- `/chapter-07/search`：搜索页。
- `/chapter-07/login`：模拟登录页。

这样做对应目标项目里的 `PageKeys`。不要把 path 字符串散落在每个按钮里。

## 第 3 步：理解 `push`、`go`、`pop`

- `context.push('/tasks/1')`：压入详情页，用户可以返回。
- `context.go('/search?keyword=x')`：切换当前 location，常用于搜索、tab、登录后回跳。
- `context.pop(result)`：关闭当前页，并把结果交回上一页。
- `context.pushReplacement('/tasks/1')`：替换当前栈顶，适合跳过登录/验证这类中间页。

在本章实验室里：

- 章节入口用 `push`，因为你从首页进入一个练习页。
- 搜索页更新 query 用 `go`，因为它是在更新当前搜索 location。
- 创建页提交用 `pop(result)`，因为创建完成后要回到列表页。
- 登录成功用 `pushReplacement`，因为登录页只是中间验证页；完成后希望栈从 `列表 -> 登录 -> 详情` 变成 `列表 -> 详情`。

### go_router 跳转方式完整对照表

| 方法 | 栈变化 | 适合场景 | 不适合场景 | 记忆方式 |
| --- | --- | --- | --- | --- |
| `context.push<T>(path)` | 新页面压到栈顶，旧页面还在下面 | 列表进详情、打开创建页、进入选择器，并等待返回值 | 中间验证页；用户不该返回它 | “再叠一页” |
| `context.pushNamed<T>(name, ...)` | 和 `push` 一样，只是用 route name 生成路径 | 大项目集中管理路由名和参数 | 小 demo 初学阶段过早复杂化 | “命名版 push” |
| `context.go(path)` | 切换到目标 location，可能重建路由栈 | 搜索、tab、首页模块切换、deep link | 需要保留来源页并让系统返回回去 | “切到这里” |
| `context.goNamed(name, ...)` | 和 `go` 一样，只是用 route name 生成路径 | 目标项目里通过 `PageKeys` 跳转 | 只写一两个页面的小练习 | “命名版 go” |
| `context.pushReplacement(path)` | 替换当前栈顶，保留下层页面 | 登录/验证/配置完成后进入目标页 | 普通详情跳转；否则可能替掉不该替的页面 | “当前页完成使命，换成目标页” |
| `context.pushReplacementNamed(name, ...)` | 和 `pushReplacement` 一样，只是用 route name 生成路径 | 大项目里的登录后回跳、支付完成页替换 | 没有命名路由规范时 | “命名版 pushReplacement” |
| `context.replace(path)` | 替换当前栈顶，并复用 page key | 同页面形态下换 id、同步底层路由状态 | 需要一个新页面生命周期和转场动画时 | “当前位置悄悄改成另一个位置” |
| `context.replaceNamed(name, ...)` | 和 `replace` 一样，只是用 route name 生成路径 | 命名路由版原地替换 | 普通页面跳转 | “命名版 replace” |
| `context.pop()` | 弹出当前页面 | 返回上一页、关闭弹窗、取消流程 | 不确定有无上一页时盲目调用 | “关掉当前页” |
| `context.pop(result)` | 弹出当前页，并把结果返回给上一页 | 创建完成、选择图片、裁剪完成 | 跨页面长期共享状态 | “带着结果关掉当前页” |
| `context.canPop()` | 不改栈，只判断有没有上一页 | 自定义 Back/Home 按钮兜底 | 当成跳转方法使用 | “能不能关掉当前页” |
| `context.namedLocation(name, ...)` | 不跳转，只生成 location 字符串 | redirect 里生成目标 URL，或先拼路径再决定跳转方式 | 直接替代 `go/push` | “只造地址，不出发” |
| `GoRouter.of(context).xxx(...)` | 与对应的 `context.xxx` 一样 | 封装工具类、没有直接使用 extension 风格时 | 页面里到处写得太重 | “router 实例版” |

所以不是“只有 4 个方法”，而是本章最常需要判断的是 `push`、`go`、`pushReplacement`、`pop(result)`。其他方法主要是命名路由、状态保留、兜底返回和封装场景。

### 不常用但要认识的栈操作

| 方法 / 能力 | 做什么 | 适合场景 | 学习时的判断 |
| --- | --- | --- | --- |
| `Navigator.of(context).push(route)` | Flutter 原生方式，手动压入一个 `Route` 对象 | 自定义转场、局部 Navigator、教学演示 `PageRouteBuilder` | 能不用就先用 `go_router`，除非你真的需要原生 Route |
| `Navigator.of(context).pushReplacement(route)` | 原生方式替换当前栈顶 | 不经过 `go_router` 的局部流程页替换 | 和 URL / deep link 同步弱 |
| `Navigator.of(context).pushAndRemoveUntil(route, predicate)` | 压入新页面，并按条件清掉旧页面 | 登出后清空业务栈、引导流完成后清掉中间页 | 力度很大，生产项目要集中封装 |
| `Navigator.of(context).popUntil(predicate)` | 连续出栈直到满足条件的页面 | 从深层流程直接回到某个已存在页面 | route name 要稳定，否则 predicate 很脆 |
| `Navigator.of(context).maybePop(result)` | 能返回就返回，不能返回就不硬弹 | 自定义返回按钮、弹窗关闭兜底 | 和 `context.canPop()` 是相近思路 |
| `Router.neglect(context, () { ... })` | 跳转时不写入浏览器 history | Flutter Web 临时改 URL，不希望浏览器后退回去 | 移动端阶段很少用 |
| `GoRouter.of(context).restore(matchList)` | 恢复一组底层路由匹配结果 | 状态恢复、路由框架内部流程 | 普通业务页面基本不直接调用 |
| `GoRouter.of(context).refresh()` | 重新触发路由刷新和 redirect 判断 | 登录态、权限态、初始化态变化后重新判断路由 | 它不是跳转，只是让路由重新计算 |
| `context.popUntil(routeName)` | `flutter-spell-ai` 封装：按页面名回到指定页 | 生成结果页、支付/登录等深层流程回到 Home 或项目页 | 不是 go_router 标准 API，要看项目 observer |
| `context.popExpression((pageName) => ...)` | `flutter-spell-ai` 封装：按条件回到某类页面 | 目标页不是固定一个 name，而是一组可能页面 | 读实现时看 `navigator_observer.dart` |
| `ShellRoute` / 嵌套 `Navigator` | 给 Tab、底部导航、模块区创建独立子栈 | 首页多 tab，每个 tab 保留自己的详情返回栈 | 它是栈结构设计，不是按钮点击 API |

## 第 4 步：区分 path、query、extra

详情页同时展示三种参数：

- path：`/chapter-07/tasks/task-101` 里的 `task-101`。
- query：`?tab=notes` 里的 `notes`。
- extra：列表页点击任务时顺手传过去的 `RouteLabTask` 对象。

关键判断：

- 资源身份放 path。
- 可选页面状态放 query。
- 复杂对象可以放 extra，但页面不能只靠 extra 活着。

直接打开链接、redirect 回来、热重启或进程恢复时，extra 可能为空。详情页至少要能从 path id 重新查询或兜底展示。

## 第 5 步：处理页面返回值

列表页打开创建页：

```dart
final draft = await context.push<RouteLabTaskDraft>('/chapter-07/create');
```

创建页提交：

```dart
context.pop(RouteLabTaskDraft(title: title, note: note));
```

这对应移动端常见流程：选择图片、裁剪图片、创建草稿、选择滤镜后，把结果返回给上一页继续处理。

## 第 6 步：理解 redirect

本章用 `RouteLabSession` 模拟登录态。

- 未登录访问 `/chapter-07/tasks/:taskId`，先跳到 `/chapter-07/login?from=原地址`。
- 登录后用 `pushReplacement(from)` 替换登录页，让详情页系统返回时回到路由实验室列表，而不是因为没有上一页而退出 App。

重点不是做真实登录，而是理解 redirect 的位置：它发生在路由层，页面真正 build 之前。
同时要分清责任：redirect 只负责拦截未登录的详情页；登录成功后的“中间页出栈策略”放在登录页动作里处理。

## 第 7 步：回到目标项目

读目标项目时按这条链路看：

1. 先看按钮或手势里调用了哪个 `Pages.toXxx(context, ...)`。
2. 跳到 `Pages.toXxx`，看它把参数放进 query 还是 extra。
3. 跳到 `PageKeys.xxx.show`，看它最终调用 `router.push/go/replace` 哪一种。
4. 跳到 `routers.dart` 里的 `AppRoute`，看 builder 如何从 `GoRouterState` 取参数。
5. 最后看页面构造函数，确认参数是否有兜底和类型约束。

## 完成标准

1. 新增一个路由 path。
2. 从按钮跳转到它。
3. 用 path 参数打开详情页。
4. 用 query 参数表达筛选状态。
5. 用 `extra` 传一次性复杂对象。
6. 用 `pop(result)` 返回创建结果。
7. 用 redirect 保护一个页面。
8. 在目标项目里追踪一条 `Pages.toXxx` 链路。
