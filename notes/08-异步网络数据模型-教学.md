# 08 异步、网络与数据模型 - 教学正文

这一章是很多 Flutter 项目的核心骨架：请求、模型、错误、缓存、异步状态。

## 先看结论

你可以把它拆成四层：

1. 网络层负责拿数据。
2. Repository 层负责屏蔽细节。
3. Model 层负责表达数据结构。
4. UI 层负责展示状态。

## 本章教学闭环

这一章按“数据流”讲，不按 API 名字背。

```text
UI 点击/进入页面
→ Repository.loadTasks()
→ ApiClient.fetchGenerationTasks()
→ JSON payload
→ Model.fromJson()
→ Result: loading / success / error
→ UI 根据状态渲染
```

Web 前端可以类比成：

- `FakeSpellApiClient` 像一个缩小版 `axios instance`。
- `SpellTaskRepository` 像 service/query function。
- `SpellGenerationTask` 像 TypeScript DTO，但 Dart 运行时不会保留 TS 那种类型擦除模型，所以 JSON 转换要更明确。
- `SpellTaskResult` 像 React Query 的 `isLoading/error/data`，只是这里手写出来帮助理解。

## 第 1 步：先分清 Future 和 Stream

先记住：

- `Future` = 一次性结果
- `Stream` = 持续变化的数据流

大多数请求接口都从 `Future` 开始。

## 第 2 步：理解 Dio 和拦截器

Dio 相当于更完整的请求客户端。

拦截器常用来做：

- 注入 token
- 统一错误处理
- 日志
- 重试

## 第 3 步：理解 Repository

Repository 的作用是把“怎么请求”从“怎么用数据”里拆出来。

这样页面和网络细节就不会互相绑死。

## 第 4 步：理解 model 与 JSON

你要习惯把数据结构写成 class，而不是在页面里到处写 Map。

重点理解：

- 字段映射
- 默认值
- 空值处理
- 枚举序列化

## 第 5 步：做一个模拟 API

建议你练：

- `ApiClient`
- `fromJson/toJson`
- loading / error / success 三态

这会帮你把异步链条跑通。

课堂操作：

1. 打开首页，进入 `08 异步网络数据模型`。
2. 观察页面进入后先显示 `loading：正在模拟请求任务列表`。
3. 等待列表出现，读每张任务卡里的 `id / prompt / status`。
4. 点击 `模拟错误`，确认 UI 进入 `error：模拟 DioException...`。
5. 点击 `重新加载成功`，确认错误态不是死状态。
6. 打开 `spell_generation_models.dart`，手动改一个 JSON 字段名，再跑测试，观察 roundtrip 为什么会失败。

这个练习故意不接真实网络。它要训练的是分层和状态，而不是 HTTP 本身。

## 第 6 步：回到目标项目

优先读：

- `/Users/dev/Documents/Projects/flutter-spell-ai/lib/repository/remote/`
- `/Users/dev/Documents/Projects/flutter-spell-ai/lib/engine/net/`
- `/Users/dev/Documents/Projects/flutter-spell-ai/lib/exception/`
- `/Users/dev/Documents/Projects/flutter-spell-ai/lib/model/result.dart`

重点看：

1. API 的统一入口在哪。
2. 错误怎么往 UI 传。
3. 哪些 model 是业务核心。

本轮已观察到：

- `lib/repository/remote/api.dart` 是远程 API 大入口，内部使用 `appDio`、`postPlus`、`get` 和 `DioPlusOptions`。
- `performDraw`、`queryDrawProcess`、`performOneImageToVideoDraw` 等方法会把页面参数模型转换为接口 body，再用 `DrawResultModel.fromJson`、`VDrawResultModel.fromJson` 等模型解析响应。
- `lib/model/result.dart` 提供 `Result.loading/data/error`、`VariableList` 等状态封装。
- `lib/model/app_error.dart` 会把 `DioException` 按网络、超时、取消、未授权、服务端错误等类型归类。
- `lib/model/` 里大量 `*.g.dart` 是生成文件，理解即可，不要手改。

读目标项目时，不要从 `api.dart` 顶到尾硬读。更好的方式是选一个页面按钮，追踪它调用的 API、参数模型、返回模型和 UI 状态。

## QA 问答

### Q1：为什么 model 最好单独定义？
因为类型安全、可维护性和序列化一致性都更好。

### Q2：为什么请求层和页面层要分开？
因为页面不该直接知道 token、重试、错误码这些网络细节。

### Q3：什么时候需要 `build_runner`？
当你用了自动生成的序列化、本地化、代码模板时。

### Q4：为什么错误不能只在 UI 里处理？
因为网络失败、权限失败、业务失败、数据失败的处理方式不同。

### Q5：为什么 JSON 模型自动生成很重要？
因为字段改动频繁时，手写映射很容易漏和错。
