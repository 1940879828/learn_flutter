# 08 异步、网络与数据模型 - 教学正文

这一章是很多 Flutter 项目的核心骨架：请求、模型、错误、缓存、异步状态。

## 先看结论

你可以把它拆成四层：

1. 网络层负责拿数据。
2. Repository 层负责屏蔽细节。
3. Model 层负责表达数据结构。
4. UI 层负责展示状态。

## 练习文件

- `notes/08-异步网络数据模型.md`

## 第 1 步：先分清 Future 和 Stream

先记住：

- `Future` = 一次性结果
- `Stream` = 持续变化的数据流

大多数请求接口都从 `Future` 开始。

## 第 2 步：理解 Dio 和拦截器

Dio 相当于更完整的请求客户端。

拦截器常用来做：

- 注入 token
- 统一错误处理
- 日志
- 重试

## 第 3 步：理解 Repository

Repository 的作用是把“怎么请求”从“怎么用数据”里拆出来。

这样页面和网络细节就不会互相绑死。

## 第 4 步：理解 model 与 JSON

你要习惯把数据结构写成 class，而不是在页面里到处写 Map。

重点理解：

- 字段映射
- 默认值
- 空值处理
- 枚举序列化

## 第 5 步：做一个模拟 API

建议你练：

- `ApiClient`
- `fromJson/toJson`
- loading / error / success 三态

这会帮你把异步链条跑通。

## QA 问答

### Q1：为什么 model 最好单独定义？
因为类型安全、可维护性和序列化一致性都更好。

### Q2：为什么请求层和页面层要分开？
因为页面不该直接知道 token、重试、错误码这些网络细节。

### Q3：什么时候需要 `build_runner`？
当你用了自动生成的序列化、本地化、代码模板时。

### Q4：为什么错误不能只在 UI 里处理？
因为网络失败、权限失败、业务失败、数据失败的处理方式不同。

### Q5：为什么 JSON 模型自动生成很重要？
因为字段改动频繁时，手写映射很容易漏和错。
