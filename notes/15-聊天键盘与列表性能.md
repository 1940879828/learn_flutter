# 15 聊天键盘与列表性能

## 学习目标

- 复刻聊天页输入框聚焦后，键盘弹起导致整页参与布局动画的场景。
- 理解 `MediaQuery.viewInsets`、原生逐帧 keyboard inset、`Scaffold.resizeToAvoidBottomInset`、底部输入栏和消息列表之间的布局关系。
- 从 Web 前端经验迁移到 Flutter：键盘不是普通 DOM resize，输入法、焦点、列表可视范围和重绘成本会一起影响手感。

## Web 前端迁移映射

在 Web 里，移动端键盘弹起常见表现是 viewport 高度变化、fixed 底栏位置变化、列表滚动位置被浏览器调整。Flutter 中内置的核心信号是 `MediaQuery.viewInsets.bottom`，它表示键盘等系统遮挡区域，但在部分 Android/输入法组合上可能不是逐帧同步的动画高度。

如果直接把键盘高度作用到整个聊天页面，顶部标题、历史消息列表、输入框会在同一次布局变化里一起移动。静态消息看起来问题不大，但真实业务里的消息项可能包含图片、视频、富文本、Hero、动画和网络图片，代价会放大。

更接近原生手感的方向，是由 Android `WindowInsetsAnimationCompat`、iOS keyboard frame / display link 这类原生机制逐帧提供键盘高度，再让 Flutter 侧只更新一个轻量 wrapper 的 transform，避免整棵页面因为读取 `MediaQuery` 反复 rebuild。

## 最小练习

配套代码：`lib/chapter_15/chat_keyboard_jank_page.dart`

练习页使用静态长消息列表、两张图片消息和原生 `TextField` 复刻现象：

- 在 iOS/Android 模拟器或真机上点击输入框后，由系统弹出默认键盘。
- 当前页面关闭 `Scaffold` 自动避让：`resizeToAvoidBottomInset: false`。系统键盘仍会弹出，但 body 不再自动压缩。
- 页面接入仓库内本地插件 `keyboard_insets_adapter`，由原生逐帧键盘高度驱动页面内 `_KeyboardTranslatedPane` 的 `Transform.translate`，把消息列表和 prompt 输入栏整体视觉上移，同时让顶部状态条和会话 header 保持不动，避免用 `MediaQuery.viewInsets` 作为动画源。
- `_KeyboardTranslatedPane` 通过 `ValueListenableBuilder.child` 固定复杂聊天子树，键盘每帧变化时只更新外层 transform，不引入第三方包里的 `KeyboardAvoidingView`、`KeyboardAwareScrollView`、`KeyboardChatScrollView`、`KeyboardToolbar` 或 `KeyboardStickyView`。
- 列表刻意使用静态 children 而不是懒加载 builder，并插入图片消息，用来放大复杂历史消息在键盘动画期间的构建和布局压力。
- 页面顶部状态条显示参与布局变化的历史消息数量，帮助观察性能风险边界。

## 目标项目观察

`flutter-spell-ai` 的聊天页输入区位于 `lib/ui/pages/chat/widget/chat_bottom_bar.dart`，主聊天页通过 `part` 拆分出 `chat_page.ui.dart`、`chat_page.menu.dart`、`widget/chat_bottom_bar.dart` 等文件。

当输入框聚焦导致键盘弹起时，如果布局策略让聊天列表整体响应键盘高度，就容易出现历史消息、顶部区域、输入栏在同一动画中移动。后续优化应先确认真实页面是由 `Scaffold` 自动 resize、手动 padding、`AnimatedPositioned`、`MediaQuery.viewInsets`，还是滚动控制逻辑触发的整体移动。

如果真实页面也需要“整体上移”，优先验证原生逐帧 inset 驱动轻量 wrapper 的方案；只有确认 Flutter wrapper 每帧更新仍然卡，才继续评估更高风险的原生直接 transform FlutterView。

## 完成标准

- 能从首页打开 `15 聊天键盘上移动画`。
- 在 iOS/Android 模拟器或真机上点击输入框后，可以看到系统默认键盘弹起，顶部 header 保持不动，消息列表和输入栏整体上移。
- 能通过顶部状态条观察 native keyboard height/progress 和视觉位移变化。
- 能解释为什么这个复刻场景会让复杂历史消息列表在键盘动画期间产生性能压力，以及为什么 native 逐帧 inset 比 `MediaQuery.viewInsets` 更适合作为动画源。
