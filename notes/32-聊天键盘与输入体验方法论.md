# 32 聊天键盘与输入体验方法论

## 这份手册解决什么问题

聊天页输入体验牵涉键盘高度、焦点、列表滚动、输入栏定位、图片/视频消息、富文本、系统输入法和性能。它不是一个 `TextField` 加 `ListView` 就结束。

这份手册用于设计聊天页、prompt 输入页和底部输入栏时，避免键盘动画卡顿、布局抖动和消息列表错位。

## 什么时候使用

- 适合：聊天页、AI prompt 输入、评论输入、底部输入栏、键盘联动页面。
- 不适合：普通表单页或不需要键盘联动的简单输入框。

## 一句话原则

键盘动画期间只移动必要的轻量区域，不让整棵复杂消息树反复参与布局。

## 决策表

| 场景 | 选择 | 原因 |
| --- | --- | --- |
| 简单表单 | `resizeToAvoidBottomInset` | 默认行为足够 |
| 聊天输入栏 | 手动控制底部区域 | 保持列表和输入栏关系 |
| 复杂历史消息 | 懒加载 + 稳定 item 尺寸 | 降低 rebuild/layout 成本 |
| 键盘动画不顺 | 原生逐帧 inset | 比 `MediaQuery.viewInsets` 更贴近系统 |
| 顶部 header | 固定在键盘位移层外 | 避免整页上移 |
| 图片/视频消息 | 固定尺寸和占位 | 避免加载后跳动 |
| 发送后 | 滚动到底部策略 | 避免遮挡新消息 |
| 输入草稿 | 局部状态或 provider | 防止页面重建丢输入 |

## 固定检查问题

```text
键盘弹起时，哪些区域真的需要移动？
历史消息列表是否在键盘动画期间重建？
输入栏高度变化是否会导致列表跳动？
图片/视频消息加载前后高度是否稳定？
发送、收起键盘、返回页面后滚动位置是否合理？
```

## Flutter 实现拆分

```text
Chat page shell
  固定 header、列表区域、输入栏层级。

Message list
  懒加载、稳定尺寸、滚动控制。

Input bar
  TextField、附件、发送按钮、草稿状态。

Keyboard adapter
  MediaQuery 或原生逐帧 inset 的统一封装。

Performance guard
  图片占位、RepaintBoundary、局部 rebuild。
```

## 常见坏味道

- 键盘高度作用到整个页面，header、列表、输入栏一起 layout。
- 消息列表用静态 children，历史消息多时仍全量构建。
- 输入栏高度变化没有同步列表底部 padding。
- 图片消息没有占位，加载后撑开。
- 每次输入文字都重建整个聊天页。
- 发送后滚动到底部和键盘动画互相抢位置。

## 验收标准

- 键盘弹起/收起动画顺滑，header 不乱动。
- 输入文字只重建输入栏必要区域。
- 历史消息列表懒加载，图片/视频尺寸稳定。
- 发送、换行、收起键盘、返回页面路径都可用。
- 真机观察 native keyboard height/progress 和 UI 位移是否一致。
