# 23 本地存储选型方法论

## 这份手册解决什么问题

移动端本地数据不是都能当 `localStorage`。配置、草稿、历史记录、媒体文件、缓存、敏感 token、系统相册，各自的生命周期、容量、权限和清理策略都不同。

这份手册用于新增本地数据前判断应该放在哪里。

## 什么时候使用

- 适合：保存开关、已读状态、草稿、历史列表、图库记录、下载文件、缓存媒体。
- 不适合：只在当前 Widget 生命周期内使用的临时变量。

## 一句话原则

先按数据大小、结构化程度、生命周期和敏感性选存储，再写读写代码。

## 决策表

| 数据 | 选择 | 原因 |
| --- | --- | --- |
| 布尔开关、已读标记、最近一次选择 | `shared_preferences` / Prefs | 小而简单 |
| 用户偏好配置对象 | JSON 文件 / AppStorage | 有结构但查询少 |
| 历史记录、草稿、图库列表 | SQLite / DAO | 需要查询、更新、分页 |
| 图片、视频、下载资源 | app files / cache directory | 大文件不进数据库 |
| 临时处理中间文件 | temp directory | 可清理，不承诺长期存在 |
| 登录 token / 敏感凭据 | secure storage / SDK 内部 | 需要安全边界 |
| 用户系统相册文件 | photo library | 受系统权限控制 |

## 固定检查问题

```text
数据是否需要跨启动保留？
数据是否需要查询、排序、分页？
数据体积会不会很大？
用户退出登录时是否要清理？
系统卸载、备份、缓存清理会怎样影响它？
```

## Flutter 实现拆分

```text
Preferences
  轻量 key-value。

FileStore
  JSON、图片、视频、下载文件。

DAO / Database
  结构化列表和查询。

Repository
  对页面提供统一读写语义。

Cleanup policy
  处理缓存过期、退出登录、临时文件清理。
```

## 常见坏味道

- 大 JSON、图片路径列表、复杂对象全塞 prefs。
- 图片/视频二进制塞进数据库。
- 文件路径写死，不用 `path_provider`。
- 只记录文件路径，不处理文件已被系统清理。
- 退出登录后本地用户数据残留。
- 缓存没有大小或过期策略。

## 验收标准

- 能说明每类数据的存储位置和清理时机。
- App 重启后数据恢复正确。
- 文件不存在、权限拒绝、缓存清理都有兜底。
- 敏感数据不进入日志、源码或普通 JSON 文件。
- 数据结构变化有迁移或兼容方案。
