# 13 多语言与本地化 - 教学正文

这一章先把多语言拆成一个很小的模型：用 key 找模板，用 locale 选语言，用参数替换占位符。

## 先看结论

多语言链路是：

```text
.arb 源文案
→ flutter gen-l10n
→ localization_intl_*.dart
→ MaterialApp.localizationsDelegates / supportedLocales
→ L.of(context).xxx
→ UI 文案
```

## 第 1 步：理解 key

不要把多语言理解成“替换字符串”。真正稳定的是 key。

例如：

- `title`
- `welcome`
- `credits`

UI 只关心 key，不关心当前语言到底显示英文、中文还是日文。

## 第 2 步：理解占位符

`{name}`、`{count}` 这类占位符对应 Web 里的 `t('welcome', { name })`。

本章 demo 里：

- `Welcome back, {name}`
- `剩余 {count} 个金币`
- `{name} さん、おかえりなさい`

这些说明不同语言不只是替换词，还可能改变语序。

## 第 3 步：理解 fallback

fallback 不是最终方案，而是防止缺翻译时 UI 崩掉或显示空白。

本章 demo 故意让中文和日文缺少 `missingOnlyInEnglish`，页面会回退到英文。

真实项目里更好的做法是补齐所有 `.arb`，不要长期依赖 fallback。

## QA 问答

### Q1：为什么多语言会影响布局？
不同语言长度差异很大，按钮、标题、弹窗都可能溢出，所以多语言不仅是文案问题，也是 UI 适配问题。

### Q2：为什么要写 description？
`.arb` 里的 description 给翻译和维护者解释语境，避免同一个英文词在不同业务里翻错。

### Q3：什么时候跑 `flutter gen-l10n`？
修改 `.arb` 源文件后跑。生成文件变化应来自命令，而不是手改。
