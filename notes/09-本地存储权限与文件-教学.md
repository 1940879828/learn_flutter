# 09 本地存储、权限与文件 - 教学正文

这一章要解决的是移动端和 Web 最大的差异之一：文件和权限不是抽象概念，而是平台能力。

## 先看结论

先把本地存储分成三类：

1. 轻量配置
2. 结构化数据
3. 真正的文件

## 本章教学闭环

先问一个问题：你到底在保存什么？

```text
一个开关/最近输入
→ shared_preferences / Prefs

一组可查询记录
→ sqflite / DAO

一张图片或一个视频
→ path_provider 目录 + File + 相册保存 + 权限
```

Web 前端可以类比：

- `localStorage` 接近 shared_preferences，但移动端还要考虑备份、卸载、平台目录。
- `IndexedDB` 的结构化查询心智可迁移到 sqflite。
- `Blob/File/Cache API` 的一部分心智可迁移到 Dart `File`，但移动端有沙箱和系统相册的边界。
- 浏览器权限和移动端权限相似，但 iOS/Android 还需要原生配置和审核语义。

## 第 1 步：分清存储类型

你要先知道自己存的是什么：

- 一个开关或 token
- 一组历史记录
- 一张图片或一个视频文件

不同的数据，选型完全不同。

## 第 2 步：理解路径和沙箱

移动端不是浏览器。

你不能假设文件路径固定，也不能假设用户能直接访问你的所有目录。

通常要通过标准库或插件拿目录，而不是自己硬写路径。

## 第 3 步：理解权限

权限在移动端是“按场景请求”的。

你要分清：

- 相册权限
- 相机权限
- 麦克风权限
- 文件权限

更重要的是，要考虑拒绝、受限、仅部分授权这些状态。

## QA 问答

### Q1：`shared_preferences` 和 `sqflite` 怎么选？
轻量配置用前者，结构化数据和查询用后者。

### Q2：为什么不能一启动就把所有权限都问完？
因为用户体验和平台审核都更偏向按需请求。

### Q3：`iOS limited` 是什么意思？
就是“授权了，但只给你部分照片访问范围”。

### Q4：为什么路径要通过插件拿？
因为不同平台、不同设备的沙箱结构不同，不能写死。

### Q5：保存媒体失败最常见的原因是什么？
权限、路径、文件损坏、重复写入、平台限制。
