# 30 动效与转场选择方法论

## 这份手册解决什么问题

动效不是“让页面更炫”。好的动效说明层级、方向、因果和反馈；差的动效增加等待、打断任务、制造掉帧。

这份手册用于判断什么时候用页面转场、Hero、错峰、属性动画、`flutter_animate`，什么时候应该保持安静。

## 什么时候使用

- 适合：页面切换、卡片展开、结果出现、按钮反馈、列表进场、共享元素。
- 不适合：高频输入、长列表滚动、性能紧张、用户急于完成任务的路径。

## 一句话原则

动效先服务信息关系，再服务视觉趣味。

## 决策表

| 场景 | 选择 | 原因 |
| --- | --- | --- |
| 普通页面进出 | route transition | 表达方向和层级 |
| 列表卡片到详情 | Hero / shared element | 保持对象连续性 |
| 多个 item 首次出现 | staggered | 降低突然感 |
| 按钮轻反馈 | scale/fade | 低成本确认点击 |
| 同页状态切换 | AnimatedContainer / AnimatedSwitcher | 表达状态变化 |
| 复杂时间轴 | AnimationController | 需要精细控制 |
| 键盘联动 | 原生 inset + 轻量 transform | 避免每帧重 layout |
| 列表中大量特效 | 少用或隔离 | 控制 raster 成本 |

## 固定检查问题

```text
这个动效表达了什么关系？
用户是否需要等待它结束才能继续？
动画每帧是否触发布局、图片解码或大范围 rebuild？
能用 transform/opacity 表达吗？
低端机或真机上是否掉帧？
```

## Flutter 实现拆分

```text
Route layer
  PageRouteBuilder / go_router page transition。

Widget layer
  AnimatedSwitcher、AnimatedContainer、Hero、flutter_animate。

Controller layer
  AnimationController 只用于复杂、可控时间轴。

Performance boundary
  RepaintBoundary、child 缓存、稳定尺寸。
```

## 常见坏味道

- 为了好看给每个列表 item 加复杂阴影、clip、blur。
- 动画每帧改高度、padding、约束，导致 layout 抖动。
- `AnimatedBuilder` 里重建整个复杂子树。
- 转场时间太长，阻碍任务。
- Hero tag 不稳定或重复。
- debug 模拟器看着顺，真机 profile 掉帧。

## 验收标准

- 动效目的能一句话说清。
- 返回和进入方向一致。
- 动画期间不触发无关网络请求或重计算。
- 复杂子树作为 `child` 缓存或隔离。
- 真机或 profile 模式验证关键路径。
