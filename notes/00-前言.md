# 00 前言

## 这个学习项目解决什么问题

这个仓库用于把已有的 Web 前端经验迁移到 Flutter/Dart，并最终具备接手 `/Users/dev/Documents/Projects/flutter-spell-ai` 的能力。

目标不是从零学习编程，也不是泛泛看 Flutter 教程，而是建立一条清晰路径：

1. 先系统掌握 Dart 和 Flutter 的核心模型。
2. 再用小练习把概念跑通。
3. 最后回到 `flutter-spell-ai`，理解真实项目的目录、依赖、状态、路由、网络、媒体和发布链路。

## 用户背景

- 已熟悉 Nuxt、Next、TypeScript。
- 已理解组件化、路由、状态、请求、构建、工程化等 Web 前端概念。
- 当前缺口主要是 Dart 语言、Flutter 渲染/布局模型、移动端能力、插件生态、真机调试和目标项目业务结构。

## 学习原则

- 用 Web 前端经验做迁移，但不强行把 Flutter 理解成浏览器。
- 每章都要有最小练习，不只看概念。
- 每章都要连接到 `flutter-spell-ai` 的真实代码。
- 先学稳定核心，再学目标项目复杂模块。
- 音视频、图库、权限、文件和性能单独重视，因为它们是目标项目的重要能力。

## 阶段目标

### 阶段一：Flutter/Dart 基础

能读懂 Dart 语法、Widget 树、布局、资源、生命周期、异步和测试。

### 阶段二：应用骨架能力

能做页面、路由、状态管理、网络请求、模型序列化、本地存储和权限处理。

### 阶段三：媒体能力

能理解图片选择、相册访问、视频播放、音频/视频资源、权限、缓存、文件保存和移动端平台差异。

### 阶段四：接手目标项目

能从入口、路由、状态、数据流和业务模块入手，逐步修改 `flutter-spell-ai` 中的小功能。

## 完成标准

当你能做到下面这些，就可以进入“接手项目”阶段：

- 能解释 Dart 和 TypeScript 的关键差异。
- 能独立写一个包含多个页面、异步请求、状态管理和媒体预览的 Flutter 小应用。
- 能读懂 `flutter-spell-ai` 的 `pubspec.yaml`、`lib/app.dart`、`lib/entry.dart`、`lib/routing/`、`lib/repository/`、`lib/model/` 和媒体相关页面。
- 能根据报错定位是 Dart 语法、Flutter 布局、插件权限、平台配置还是业务数据问题。

## QA 问答（面试官常问）

### Q1：为什么要先系统学 Flutter/Dart，再接手复杂业务项目？
因为复杂业务项目有大量框架约定和状态边界，先补齐框架语义才能高效定位问题，避免把“框架不熟”当成“业务不懂”的错觉。

### Q2：你会用什么指标判断自己可以接手生产项目？
是否能快速定位入口、路由、状态、网络、数据模型、媒体和权限链路，并能提出小步修改计划。面试里通常会问“风险意识如何体现”。

### Q3：Web 前端经验在 Flutter 学习中哪个最容易误用？
最容易误用的是“把 Flutter 当 DOM 看待”。面试里常问到架构迁移意识，重点在于理解渲染和状态机制不同。
