# 25 媒体能力链路方法论

## 这份手册解决什么问题

图片、视频、音频不是一个 Widget 能解决的能力。它们涉及来源、权限、文件、缓存、解码、播放器生命周期、列表可见性、保存相册和失败恢复。

这份手册用于设计媒体功能的完整链路，而不是只把图片或视频显示出来。

## 什么时候使用

- 适合：选图、预览、上传、视频播放、结果保存、媒体列表、音频能力预研。
- 不适合：只展示一个固定 asset 图标。

## 一句话原则

媒体功能先画来源和生命周期，再写播放器或预览 Widget。

## 决策表

| 场景 | 关键设计 | 原因 |
| --- | --- | --- |
| asset 媒体 | pubspec 声明 | 构建期打包 |
| network 媒体 | 缓存、失败、占位 | 网络不可控 |
| file 媒体 | 路径有效性、清理 | 文件可能消失 |
| 图片列表 | 缩略图、固定尺寸 | 避免解码和布局抖动 |
| 视频详情 | controller 生命周期 | 避免黑屏和泄漏 |
| 视频列表 | 可见性创建/释放 | 控制资源占用 |
| 保存相册 | 权限 + 文件校验 | 系统能力敏感 |
| 音频播放 | 焦点、后台、进度 | 插件和平台差异大 |

## 固定检查问题

```text
媒体来源是 asset、network、file，还是系统相册？
文件是否可能被清理、移动或损坏？
列表里是否需要缩略图而不是原始媒体？
播放器何时 initialize、play、pause、dispose？
失败后用户能重试、换文件、还是去设置？
```

## Flutter 实现拆分

```text
Picker / Importer
  负责选择、权限和导入。

Media model
  表达来源、路径、尺寸、时长、mime、状态。

Preview widget
  负责图片/视频/音频展示。

Controller manager
  管理播放器初始化、暂停、释放和独占播放。

Repository / FileStore
  管理下载、缓存、保存相册和本地记录。
```

## 常见坏味道

- 列表直接展示原图或多个自动播放视频。
- 创建播放器后不 dispose。
- 页面离开、tab 切换、App 后台时仍播放。
- 网络图没有固定尺寸，加载后撑开布局。
- 保存相册失败只显示通用错误。
- 音频能力没做焦点、后台、权限预研就直接接插件。

## 验收标准

- 每个媒体来源都有 loading、error、placeholder。
- 图片/视频列表滚动不卡顿，尺寸稳定。
- 播放器在进入、离开、不可见、后台时行为清楚。
- 保存相册区分权限、文件、系统失败。
- 真机验证关键播放和保存路径。
