# 04 布局、样式和资源 - 教学正文

这一章要解决的是两个问题：怎么让界面排对位置，怎么让资源正确进入包里。

## 先看结论

Flutter 布局最关键的心智是：

1. 约束先下发。
2. 子组件决定自己的尺寸。
3. 父组件决定摆放位置。

## 练习文件

- `notes/04-布局样式和资源.md`
- `pubspec.yaml`

## 第 1 步：先理解约束模型

不要一开始就把 Flutter 当成 CSS。

你要先接受这句：

```text
parent 给约束 -> child 选尺寸 -> parent 定位置
```

这解释了很多新手常见问题，比如为什么会 overflow、为什么某些列表一定要包一层 `Expanded`。

## 第 2 步：先会用最常见的布局组件

先把这些组件分组记：

- 单个容器：`Container`、`Padding`、`SizedBox`
- 线性布局：`Row`、`Column`、`Flex`
- 叠放布局：`Stack`、`Positioned`
- 可滚动布局：`ListView`、`GridView`、`CustomScrollView`

你不需要一口气全背完，先会判断“这是什么布局问题”。

## 第 3 步：理解响应式和安全区

移动端和 Web 不一样，顶部刘海、底部手势区、不同屏幕比例都要处理。

先记两个常用工具：

- `MediaQuery`
- `SafeArea`

它们会帮你处理屏幕尺寸和安全区边界。

## 第 4 步：理解主题和样式

Flutter 的样式不靠 CSS，而是 Widget 参数、`ThemeData`、`TextStyle`、`Color` 组合出来。

你应该先形成一个习惯：

- 页面级视觉尽量通过主题统一
- 单页特例用局部样式覆盖
- 复杂样式尽量抽公共组件

## 第 5 步：理解资源声明

Flutter 资源不是随便放个目录就能用。

你要做的是：

1. 在 `pubspec.yaml` 里声明资源
2. 跑依赖或重启
3. 在代码里引用

这和 Web 的 public folder 思路不完全一样，更偏构建时声明。

## 第 6 步：做一个最小页面

建议你做一个作品卡片列表，练到这几个点：

- 标题
- 图片
- badge
- 操作按钮
- 窄屏和宽屏都不炸

如果出现 overflow，先别急着加 `SingleChildScrollView`，先看是不是约束没收住。

## QA 问答

### Q1：为什么 `Column` 里放滚动列表容易报错？
因为 `Column` 想给子组件一个无限高的方向，而滚动列表通常需要明确高度约束。

### Q2：`Expanded` 和 `Flexible` 有什么区别？
`Expanded` 更像强制填满，`Flexible` 更像允许弹性分配。前者更“硬”，后者更“松”。

### Q3：资源为什么要在 `pubspec.yaml` 声明？
因为 Flutter 是在构建阶段把资源打进包里的，不声明就不会被打包进去。

### Q4：什么时候该用 `Stack`？
当你需要图层叠放，比如角标、浮层按钮、图片上叠文案时。

### Q5：为什么移动端要重视 `SafeArea`？
因为不同设备的刘海、状态栏、手势区会影响布局，不能直接假设屏幕四边都可用。
